# 雅可比原理页（任务书第三节）

本页用**这台机械臂自己的参数**讲清楚 `Jv[:, i] = z_i × (p_tcp − o_i)`：
为什么要叉乘、为什么有的列是零、为什么换个姿态同一列的数值就变了。

## 1. 三个关系不是一回事

```text
p = f(q)                 正运动学：给一组角度，算末端在哪
v = Jv(q) · q_dot        当前姿态下的速度关系：Jv 随 q 变
delta_p ≈ Jv(q) · delta_q   小位移近似：只在 delta_q 足够小、且不跨过 J 变化大的区域时成立
```

三点必须分清：

- `p = f(q)` 只给**位置**。要回答"转一点会往哪走"，必须对 q 求导，也就是 `Jv`。
- `Jv` 是**当前位置处**的导数，q 一变它就变。所以不能拿起始姿态算出来的 Jv 去预测
  大幅运动后的位移。
- `delta_p ≈ Jv·delta_q` 是一阶近似。误差量级约为 `O(|delta_q|²)`，任务书第五节就是
  用实验把这个误差量出来。

## 2. 一列的物理意义

`Jv` 是 `3×6`，第 i 列是一个三维向量，单位 **m/rad**。

含义：**其他五个关节保持不动、第 i 个模型关节以 +1 rad/s 转动时，TCP 线速度中由它贡献的部分**
（单位 m/s）。注意：

- 它描述的是"每弧度带来多少位移"，不是要求实机以 1 rad/s 运动；
- 六列相加才是六个关节同时运动时的合成速度，某一列大不代表那个关节一定重要，
  要看实际的 `q_dot`；
- 列的方向就是"只动这个关节时，TCP 会往哪走"。

## 3. 为什么是 `z × r`

关节是绕一根轴转的，轴上的点不动，离轴越远的点走得越快。写成一个点的速度：

```text
v = omega × r_axis
  = (q_dot · z) × (p_tcp − o)
  = q_dot · [ z × (p_tcp − o) ]
```

所以 `Jv[:, i] = z_i × (p_tcp − o_i)`，其中：

| 符号 | 含义 | 本仓库怎么取 | 单位 |
| --- | --- | --- | --- |
| `z_i` | 关节 i 的正转轴，单位向量 | `frames[i]` 的旋转矩阵第 3 列 | — |
| `o_i` | 轴线上任意一点 | `frames[i]` 的原点（第 4 列平移） | m |
| `p_tcp` | 末端工具点 | `frames[5] · tcp_local` | m |

三者**必须都在底座 {0} 里表达**。FK 算出来的 `frames[i]` 天然就在 {0} 里，所以不用再变换。

三个几何性质（图上都能看到）：

1. **方向由右手定则决定**：右手拇指指向 `+z_i`，四指弯曲的方向就是 `+q_i` 的正转方向；
   速度 `v = omega × r` 垂直于 z 和 r 构成的平面，指向由 z→r 的右手法则给出。
2. **大小等于 TCP 到轴线的垂直距离**：`|z×r| = |r|·sinθ = r_perp`，也就是该关节以
   1 rad/s 转动时 TCP 的线速度大小（m/s）；转 1 rad 时 TCP 沿圆弧走过的弧长同样是 r_perp。
3. **r 平行于 z 时为零**：点在轴上或轴的正上方，绕这根轴转它不动。

## 4. 本仓库取哪一级 frames（最容易错的地方）

Craig 改进 DH 里，关节 i 的转角写在 `A[i]` 里：

```text
A[i]      = Rx(alpha[i]) Tx(a[i]) Rz(q[i]+theta_offset[i]) Tz(d[i])
frames[i] = A[0] · A[1] · ... · A[i]
```

所以 **J_i 的轴和轴上点取 `frames[i]`**：

| 关节 | 用哪一项 | 对应图中的坐标系 |
| --- | --- | --- |
| J0 | `frames[0]` | {1} |
| J1 | `frames[1]` | {2} |
| J2 | `frames[2]` | {3} |
| J3 | `frames[3]` | {4} |
| J4 | `frames[4]` | {5} |
| J5 | `frames[5]` | {6} |

标准 DH 的索引习惯是"取前一级"，在改进 DH 下会整体错一格。对照方法：看
`frames[i]` 的原点是不是正好落在关节 i 的轴线上——比如 `frames[1]` 的原点
(0, −0.022, 0.042) 就是 J1 轴上的点。

## 5. q = 0 的完整手算例题

姿态：`q = [0,0,0,0,0,0]`，`tcp_local = [0,0,0]`，所以 `p_tcp = frames[5]` 的原点
= **(0.1895, 0.0148, 0.245) m**。

逐列（数值已与中心差分核对，最大误差 2e-11）：

| 列 | z_i | o_i (m) | r = p_tcp − o_i (m) | Jv[:,i] = z×r (m/rad) | \|v\| | 几何解释 |
| --- | --- | --- | --- | --- | --- | --- |
| J0 | (0,0,1) | (0, 0, 0.042) | (0.1895, 0.0148, 0.203) | (−0.0148, 0.1895, 0) | 0.190 | 腰：TCP 绕竖轴画圈，水平切向；0.19 就是它到竖轴的水平距离 |
| J1 | (0,1,0) | (0, −0.022, 0.042) | (0.1895, 0.0368, 0.203) | (0.203, 0, −0.1895) | 0.278 | 肩：轴沿 y，速度在 x–z 平面内，大小 0.278 是到肩轴的斜距 |
| J2 | (0,−1,0) | (−0.0015, 0.0073, 0.162) | (0.191, 0.0075, 0.083) | (−0.083, 0, 0.191) | 0.208 | 肘：轴沿 −y，与 J1 反向平行；TCP 相对这根轴的位置不同，速度方向与 J1 大致相反 |
| J3 | (−1,0,0) | (0.1095, 0.0073, 0.245) | (0.08, 0.0075, 0) | (0, 0, −0.0075) | 0.0075 | TCP 几乎在 J3 轴上，只差 7.5 mm（正是 J4 的 d），所以几乎为零 |
| J4 | (0,1,0) | (0.1095, 0.0148, 0.245) | (0.08, 0, 0) | (0, 0, −0.08) | 0.080 | 俯仰：TCP 在 80 mm 外，速度竖直向下 |
| J5 | (−1,0,0) | (0.1895, 0.0148, 0.245) | (0, 0, 0) | (0, 0, 0) | 0 | TCP 就在 J5 轴上，绕它转 TCP 不动 |

自己动手核对一列（J1）：

```text
r = p_tcp − o = (0.1895, 0.0148, 0.245) − (0, −0.022, 0.042)
              = (0.1895, 0.0368, 0.203)

z × r = (1·0.203 − 0·0.0368,
         0·0.1895 − 0·0.203,
         0·0.0368 − 1·0.1895)
      = (0.203, 0, −0.1895)      |v| = 0.278  ✓
```

算出来应该和表里一致（1e-4 以内）。对不上时按这个顺序查：`frames[i]` 取错级 →
z/o 取错行列 → r 的减号方向 → 单位/角度制。

## 6. TCP 偏置：为什么 J5 有时为零、有时不为零

| tcp_local | p_tcp (m) | J5 列 (m/rad) | 说明 |
| --- | --- | --- | --- |
| (0, 0, 0) | (0.1895, 0.0148, 0.245) | (0, 0, 0) | TCP 就是 {6} 原点，落在 J5 轴上 |
| (0, 0, 0.05) 沿轴 | (0.1395, 0.0148, 0.245) | (0, 0, 0) | **沿轴**滑 5 cm，垂直距离仍是 0 |
| (0.05, 0, 0) 垂直 | (0.1895, 0.0648, 0.245) | (0, 0, −0.05) | **垂直**偏移 5 cm，才出现 0.05 |

所以任务书里的三个问题：

- **为什么 TCP 在 {6} 原点时 J5 列为零？** 因为 `frames[5]` 的原点就在 J5 轴上，
  `p_tcp − o = 0`，叉乘为零。图上左联的 p_tcp 和 o 是同一个点。
- **为什么加了偏离轴线的 TCP 后可能非零？** 一旦 TCP 有垂直于轴的分量，`|z×r|`
  就等于这个垂直距离；偏多少，列的大小就是多少（偏 5 cm → 0.05 m/rad）。
  注意是"垂直分量"，沿轴偏多少都不算。
- **为什么位置列为零不代表该关节不改变末端姿态？** 位置雅可比只描述 TCP 的**平移**。
  J5 是腕部回转，它让末端绕自己的轴自转：`Jw[:,5] = z_5 = (−1,0,0) ≠ 0`。
  姿态角速度那一列不为零，只是不影响 TCP 的位置。

实际装夹时，TCP 一定要用真实工具点，不能默认 `[0,0,0]`——用错 TCP，J3～J5 三列的
数值会整体失真，而 J0/J1 也会因为 `p_tcp` 变了而变化。

## 7. 对 q 的雅可比 vs 对编码器的雅可比

上面的列都是对**模型角 q** 求导。固件里真正读到的是编码器角：

```text
q[i] = position_sign[i] · (encoder[i] − encoder_zero[i])
=>  J_encoder = J_q · diag(position_sign)
```

也就是说：要把某一列乘上该关节的 `position_sign`，零位 `encoder_zero` 不影响导数
（常数项求导为零）。`torque_sign` 是力矩方向的转换，**与几何无关，不参与雅可比**。

改 `position_sign` 时有两件事同时发生，回答时要**分开说**：

1. **映射变了**：同一组编码器读数被解释成不同的 q，对应的物理姿态也变了，
   所以 `J_q` 的数值跟着变——这不是"乘一个负号"能描述的；
2. **求导变量换了**：如果看的是对编码器读数的雅可比，还要按链式法则
   乘上 sign（`J_encoder = J_q·diag(sign)`）。

第 1 条是姿态变了，第 2 条是求导变量变了，不要混成一件事。

## 8. 换姿态会怎样

同一个关节在不同姿态下对 TCP 的影响完全不同，原因全在 `r = p_tcp − o`：
轴不动（在 {0} 里方向可能变），但 TCP 相对轴的位置变了，垂直距离和方向都变。

例：q = 0 时 J1 的列是 (0.203, 0, −0.1895)，|v| = 0.278；换到物理回零姿态
（q = [−0.30, −1.50, −1.65, 0.20, −0.01, 0]），这一列变成 (0.057, −0.018, −0.081)，
|v| 只有 0.101，方向也转了。同时 J0 从 0.190 降到 0.083。所以：

- 不能拿一个姿态的 Jv 当"机械臂的 Jv"；
- 做小位移预测时，"起点姿态的 Jv 预测的是起点附近"；
- 实机实验也要挑安全的中间姿态，不要在极限位置附近做。

## 10. 现场抽问自测（任务书第九节）

**1. 临时给一组 q，指出某一列的物理意义。**
那一列 = 其他关节不动、该关节以 +1 rad/s 转时 TCP 的速度（m/s），方向按右手定则，
大小等于 TCP 到该轴的垂直距离。

**2. 换 TCP 偏置，哪些列会变？J5 为什么可能从零变非零？**
所有列都可能变（`p_tcp` 变了）。J5 从零变非零的条件是偏置有垂直于 J5 轴的分量，
此时 |列| 就等于那个垂直距离；沿轴偏置不改变结果。

**3. `frames[0]` 是什么？为什么用本级 frames 的 Z 轴？**
`frames[0] = A[0]`，是过 J0 之后的坐标系 {1}；它不是在底座 {0}。因为关节 i 的转角
写在 `A[i]` 里，该关节的轴自然就是 `frames[i]` 的 z 轴。

**4. 给小 delta_q，先预测主要位移方向，再验证。**
取 J1 单独 +0.01 rad: `delta_p ≈ 0.01 × (0.203, 0, −0.1895)` = (2.0, 0, −1.9) mm，
即主要沿 +x 并略向下；用 FK 差分验证。

**5. 改 `position_sign` 的两种影响。**
① 映射翻转：同一编码器值对应不同的 q，物理姿态和 `J_q` 都变了；
② 若改看对编码器的雅可比，链式法则再给该列乘一个 sign。
①是姿态变，②是换求导变量。

**6. 数值差分通过、实机对不上，按什么顺序排查？**
测量（分辨率、基准点、重复性）→ 编码器映射（零位/符号）→ TCP（真实工具点与坐标轴）→
几何（DH 是否对应实物）→ 机构误差（间隙、柔性、连杆实际长度）。
先确认前一级没问题，再往后查。

**7. 为什么现在不能直接求逆让实机追点？**
`Jv` 是 3×6，不能求逆；即使取伪逆，也只在当前位置附近有效，遇到奇异位形速度会爆炸，
而本任务没有做奇异处理、轨迹规划和实时闭环，安全保护也不允许直接驱动。
