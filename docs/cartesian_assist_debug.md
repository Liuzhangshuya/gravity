# 末端各向异性阻抗：实机调试手册

本文对应 `User/gravity/cartesian_assist.c` / `.h` 和 `fsm.c` 里的一行调用。
目标现象：**浮动状态下手推末端，水平方向明显"顶手"，竖直方向很轻**，
松手后手臂停在原地，不会来回荡。

---

## 0. 它是什么

```
e = p_tcp - p_ref          # 末端偏离参考点，m
v = Jv * q_dot             # 末端速度（由编码器速度经雅可比得到），m/s
F = -K*e - D*v             # 虚拟末端力，N；K = diag(KX, KY, KZ)
tau_model = Jv^T * F       # 转成关节力矩
tau_motor = torque_sign * tau_model
```

`KX = KY = 120 N/m`，`KZ = 30 N/m`，所以同样推 10 mm，水平要 1.2 N，竖直只要 0.3 N。
这就是"各向异性"。师兄开源里的固件实际做的是**速度级**笛卡尔控制
（Weighted-DLS + 零空间），不是力矩级阻抗；这一层 `tau = J^T F` 是他那份代码里没有的，
也正是作业要补的部分。

## 1. 为什么默认不生效

`CartesianAssist_Run()` 的使能是三重门：

```
g_cart_assist_enable != 0  且  fsm->state == fsm_geforce_off  且  global_system_halt_flag == 0
```

- 默认 `g_cart_assist_enable = 0`，所以**不打开时力臂行为与原来逐字节一致**；
- 只在自由拖动（浮动）状态叠加，锁定、回零、测试、保护状态下 `tau_cart` 恒为 0；
- 熔断后自动不输出。

叠加位置在 `fsm.c::motor_par_send()`：

```c
Gravity_Arm_Run();
CartesianAssist_Run((uint8_t)(fsm->state == fsm_geforce_off));
float ramp = fminf(... / 500.0f, 1.0f);
```

也就是"重力前馈 + 阻抗项"，然后照旧走 `motor_protect_run()` 和 `ctrl_set()`。

## 4. 第一次上机的顺序

**前提**：指导学长/老师在现场；力臂放在支架或桌面上托住；手边就是电源开关。

1. **锁定状态**（`fsm_lock`）下进入调试，在 `main` 的断点停住，把
   `g_cart_assist_enable` 改成 `1`，`g_cart_assist_scale` 改成 `0.5f`，然后全速运行。
   此时 `enabled` 应为 `0`（不在浮动），力矩没有任何变化。
2. 按锁定键切到浮动。手臂应该和以前一样"几乎失重"。看 Watch：
   - `enabled`、`active` 变 1；
   - `gain` 从 0 升到 1 用 500 ms；
   - `p_ref` ≈ `p`，`e`、`F`、`tau_cart` 都 ≈ 0。
3. **不要推**，先等 2 秒。力矩应该稳定，手臂不下沉、不抖。
   若此步就抖或走，直接按锁定键退出（见第 8 节）。
4. 用手扶住末端，沿 **+x** 缓慢推 10 mm，看 `e[0]` 应为 **正**、`F[0]` 应为 **负**
   （`F` 和 `e` 永远反号）。松手：手臂被拉回参考点，像一根弹簧。
5. 同样试 +y。注意这一下 `tau_cart[0]` 会明显（约 −0.049 N·m / 10 mm @ scale 0.5），
   因为 home 姿态下 J0 对 y 方向力最敏感。
6. 试 ±z：同样力推，位移应该约为水平的 4 倍（软）。
7. 都正常后，把 `g_cart_assist_scale` 改回 `1.0` 再重复 4–6。
   （运行中写不了就回锁定状态、暂停、改值、继续，再切浮动。）

> 为什么先 0.5：即使力矩符号错了，0.5 倍也只是一次比一次小的推，
> 不会像满增益那样直接把手臂甩出去；同时更容易看清"哪一维不对"。

## 5. 该看到的数（home 姿态，scale = 1.0）

home = 上电回零后的姿态（编码器全 0），模型角
`q = (−0.300, −1.500, −1.650, 0.200, −0.010, 0)` rad，TCP
`p = (0.08210, −0.00989, 0.10182) m`。

雅可比（行 = x/y/z 方向，列 = J0…J5，单位 m/rad）：

```
Jx = +0.00989  +0.05715  -0.05047  -0.00128  -0.01513  +0.00000
Jy = +0.08210  -0.01768  +0.01561  -0.00034  -0.01195  +0.00000
Jz = -0.00000  -0.08135  +0.20115  -0.00743  -0.07764  -0.00000
```

每 1 N 虚拟力对应的**电机侧**力矩（已乘 `torque_sign`）：

```
1N x ->  +0.0099  -0.0571  +0.0505  -0.0013  -0.0151   0
1N y ->  +0.0821  +0.0177  -0.0156  -0.0003  -0.0120   0
1N z ->  -0.0000  +0.0814  -0.2011  -0.0074  -0.0776   0
```

位移 ↔ 力（scale = 1.0）：

| 方向 | 位移 | 力 | 备注 |
| --- | --- | --- | --- |
| x / y | 5 mm | 0.6 N | |
| x / y | 10 mm | 1.2 N | 上表 1N×1.2 就是对应 τ |
| x / y | 25 mm | 3.0 N | |
| x / y | 50 mm | 6.0 N | 到此 `FMAX` 饱和 |
| z | 10 mm | 0.3 N | 水平的 1/4 |
| z | 33 mm | 1.0 N | |
| z | 100 mm | 3.0 N | |
| z | 200 mm | 6.0 N | 饱和 |

scale = 0.5 时，同样的力对应两倍位移。

力矩余量（home，6 N 满力时）：水平 y 方向 J0 约 0.49 N·m，是它 0.6 N·m 上限的 82%；
竖直方向 J2 约 1.21 N·m，占 2.3 N·m 的 52%。**这就是 FMAX 定 6 N 的原因**：
再大，J0 会先顶到限幅，保护会介入，而且力矩分布会失真。

### 5.1 实测记录（scale = 1.0，home 附近）

| 快照 | e = [x, y, z] (mm) | F = [x, y, z] (N) | −F/e (N/m) |
| --- | --- | --- | --- |
| 1 | 8.84, −4.63, −1.47 | −1.083, +0.589, +0.047 | 122.5, 127.4, 31.7 |
| 2 | 22.40, −8.72, −34.00 | −2.753, +1.104, +1.079 | 122.9, 126.6, 31.7 |

对照设计值 K = (120, 120, 30) N/m：误差 ≤ 6%，y 方向偏高来自运动中的阻尼项。
`gain=1`、`sat_cnt=0`、`enabled=active=1`。

结论：增益、符号、各向异性比例全部正确，**验收的核心判据已通过**。

第二行还说明：推力约 2.96 N 水平 + **1.08 N 向下**（竖直分力占 34%），
所以竖直掉了 34 mm。位移比满足

```
e_z / e_x = (F_z / F_x) · (KX / KZ) = 0.39 · 4 = 1.57
```

**各向异性的代价就在这里**：竖直软 4 倍，手上一点点向下的分力就被放大 4 倍。
这 1.08 N 可能来自手，也可能是该姿态下的重力残差，用第 8 节的"纯浮动同姿态"
对比来区分。要减小竖直位移只有两条路：把手推得更水平，或降低 KX/KZ 的比值。

**为什么"前伸"不必然改变 z**：静止时平衡方程是 `e = K⁻¹·F`，这个式子里
没有关节角，也没有零位姿态。折叠零位只决定关节怎么动、每个关节分到多大力矩
（所以你会看到 J4 转得明显），不决定末端最后停在哪里。只要手是纯水平推，
末端就停在纯水平的偏移上——肩、肘、腕协同"展开"一点就能做到，
运动学上不要求 z 变化。反过来说：**静止时出现 34 mm 竖直偏移，就一定有
1.08 N 的竖直力在维持它**（手的分力、重力残差或关节摩擦）。
几何本身撑不住一个静态偏移。想验证：推的时候盯住 `F[2]`，
把手调到水平、直到 `|F[2]| < 0.2 N`，再看 `e[2]` 是不是也跟着回到 0。

### 5.2 为什么抬手臂时 J4 转得很明显

这是正常的分配结果，不是符号错。home 附近 J4 的转轴就是 +y0，竖直方向每 1 N 虚拟力，
`J^T F` 会在 J4 上要 0.078 N·m：

```
抬起末端 -> e[2] > 0 -> F[2] < 0（力向下）
tau_cart[4] = J[2][4] * F[2] = (-0.0776) * (负) = 正
正力矩 -> 绕 +y0 正转
```

也就是说，**你看到的转向正是模型预测的转向**。用力 3 N 时 J4 约 0.23 N·m，
只占它 1.2 N·m 上限的 20%。

看起来"转得厉害"是因为浮动状态 kp=0，手腕又是整条链里最轻、限幅最小的关节，
同样力矩下它动得最明显，而肩肘几乎不动。这是"只做平移"的固有现象：
位置阻抗不约束姿态，末端姿态会跟着手腕漂。想让它不漂，就是下一步的姿态（6D）
阻抗或零空间手腕保持，不是现在能靠调 K 解决的。

三个快速判据：

- `tau_cart[4] ≈ -0.0776 * F[2]`（home 附近，误差 10% 以内）；
- 抬起时末端被往下压，松手回到 `p_ref`；
- 不会越推越快（那是符号错）。

| 检查项 | 预期 | 失败含义 |
| --- | --- | --- |
| 开关=0 | `tau_cart` 全 0，行为与旧固件一致 | 叠加没接上 |
| 锁定状态 + 开关=1 | `enabled=0`，无输出 | 门控写错 |
| 进浮动 | `gain` 0→1 / 500 ms | 软启动没生效 |
| 静止 | `e`、`F`、`tau_cart` 都 ≈ 0 | `p_ref` 捕获时机不对 |
| 推 +x 10 mm | `e[0]>0`，`F[0]<0` | 符号反了 → 立刻锁定 |
| 松手 | 回到 `p_ref` 附近，不来回荡 | D 太小 |
| 水平 25 mm | 约 3 N（手感） | K 不对 |
| 竖直同样力气 | 位移约 4 倍 | KZ 没生效 |
| 快速推一下 | 明显阻尼，停下就停 | `v` 估计不对 |
| 快速推一下 | `sat_force_cnt` 会涨（阻尼力顶到 FMAX），属正常 | — |
| 慢推 10–25 mm | `sat_force_cnt`、`sat_tau_cnt` 都不涨 | K/FMAX 太大，或该姿态力矩余量不够 |

### 6.1 各向异性证据（核心，必须做）

两种做法等价，选一种即可：

- **等位移**：推到固定距离（用尺子），读力。`F_h/F_z` 应为 **4.0**。
  更好操作，推荐。
- **等力**：推到固定力，读位移。`e_z/e_h` 应为 **4.0**。

无论哪种，比较的都是"同样条件"，理论比值都来自 `KX/KZ = 120/30 = 4`，
与姿态、零位无关。通过区间 **3.5 ~ 4.5**。

#### 实测记录（home，scale = 1.0，等位移）

| 记录 | e = [x, y, z] (mm) | F = [x, y, z] (N) | 等效刚度 (N/m) |
| --- | --- | --- | --- |
| 25mm_x | 23.9, −7.3, −5.3 | −2.898, 0.846, 0.139 | 水平 **120.6** |
| 60mm_x | 57.1, −18.6, −45.1 | −5.555, 1.979, 1.190 | `\|F\|` 被裁到 6.00（未裁约 7.34） |
| 36mm_z | −5.7, 1.4, 36.4 | 0.738, −0.131, −1.110 | 竖直 **30.5** |
| 60mm_z | 10.2, −5.3, 61.1 | −1.265, 0.655, −1.835 | 竖直 **30.0** |
| 姿态 2 · 22 mm 水平 | 21.9, −6.6, −4.3 | −2.640, 0.806, 0.134 | 水平 **120.5** |
| 姿态 2 · 39 mm 竖直 | 1.7, −0.6, 38.7 | −0.188, 0.103, −1.164 | 竖直 **30.1** |

结论：水平 120、竖直 30，同样 60 mm 位移下未裁剪的力约 7.34 N 对 1.84 N，
比值 **4.0 : 1**，通过。60mm_x 那一行同时验证了 `FMAX` 裁剪：裁剪因子
`6.00 / 7.34 = 0.818`，三个分量都按同一比例缩小。

注意 60mm_x 里 `e[2] = −45 mm`：手在水平推的同时带了 1.19 N 向下的分力，
不是耦合错误（见 5.1）。

重复性：两个姿态已各测一次，等效刚度都是 120 / 30。再换一个姿态各做一次更完整。
J 会变、各关节分到的力矩会变，但等效刚度仍应是 120 / 30。

**回弹时间**：推出 25 mm 松手，通常 1–2 s 回到 `p_ref` ±5 mm；偶尔略慢，
多半是最后几毫米需要克服关节静摩擦（弹簧力 ~0.6 N 量级）。判据：
停住不动、不持续漂，就算通过。

## 7. 调参

只改三处，按顺序：

1. **`g_cart_assist_scale`**（不用重编译）：整体变软/变硬，阻尼比不变。
2. **`KX/KY/KZ`**（`cartesian_assist.h`）：各方向的硬度比例。
   想更"水平重、竖直轻"，就加大 KX/KY 或减小 KZ；保持比例 4:1 左右观感最好。
3. **`DX/DY/DZ`**：松手后荡 → 加大；觉得发涩、跟手慢 → 减小。
   现在是 `D/K ≈ 0.125`（15/120）和 `0.1`（3/30）。改 K 时按同一比例改 D，
   就不会把阻尼比改坏。

`CART_ASSIST_FMAX` 不要超过 8 N，改之前先按第 5 节算一遍对应关节力矩。
`CART_ASSIST_RAMP_MS` 只在"打开瞬间手臂被拽一下"时才需要加长。
`CART_ASSIST_TCP_(X/Y/Z)` 是工具点相对 `{6}` 的偏置，量出来再改；
不加工具就一直保持 0，否则 `p_ref`、`J` 和手感的对应关系都会变。

## 8. 出问题怎么退

- **任何时候按锁定键**：状态离开 `fsm_geforce_off`，下一周期 `enabled=0`，
  阻抗项立即归零（重力前馈和锁定照旧）。这是最快的软退出。
- 手臂自己往外跑、越推越远：**符号反了**。先锁定/断电，再核对第 5 节
  "1N 对应的力矩"表和你 Watch 里 `tau_cart` 的符号，不要靠加大 K 去压。
- 抖动/啸叫：把 `g_cart_assist_scale` 降到 0.3；仍抖就加大 D 或降低 K。
  也要确认 `fsm.c` 里浮动模式用的 `MOTOR_FLOAT_KD` 没被改过。
- 触发保护：看 `motor_protect` 的保护原因和 `sat_cnt`，降低 FMAX 或换姿态。
- **水平推时竖直跟着动**：先分清来源。
  - 手完全离开、assist 打开、静止不动，`e[2]` 仍在长 → 重力残差在姿态变化后变了；
  - 手推着的时候，竖直位移 ≈ 手上那一点竖直分力 ÷ (scale·KZ)。
    scale=1 时 0.6 N 就对应 20 mm，scale=0.5 时对应 **40 mm**——
    竖直轴的有效刚度只有 15~30 N/m，手上一点没控制住的竖直分力会被放大 4 倍，
    这不是耦合 bug。想减小：KZ 30→60（比例变 2:1），
    或用竖直的板/尺子给手做导向，减少竖直分力。
- **推不到 6 N**：静止时 `F` 永远等于你手上的力，`K` 只决定"这个力要推多远"，
  不决定力的上限。所以 `scale=2.0` 只是把 6 N 需要的位移从 50 mm 减到 25 mm，
  **手还是得推 6 N**。不必强求饱和，更直接的是看比值 `-F/e ≈ 120·scale`。
  想看裁剪真正发生：快速推一下即可——`F = -K·e - D·v`，`scale=2` 时 `D=30 N·s/m`，
  0.2 m/s 就多出 6 N 阻尼力，`sat_force_cnt` 会涨；慢推时它应保持 0。
- **`sat_cnt` 涨但 `F` 不到 6**：看是哪一半在涨。`sat_force_cnt` 涨是瞬时阻尼力顶到
  `FMAX`（正常）；`sat_tau_cnt` 涨是某个关节（home 下最常是 J0）的阻抗力矩超过
  0.8×上限，说明该姿态下这方向推不了这么大力，应降低 `scale` 或换姿态。
- 重新回零前，把 `g_cart_assist_enable` 写回 `0`，避免下次进浮动意外打开。

## 9. 姿态（6D）扩展

平移稳定后叠加的一层，**默认关闭**，开关是 `g_cart_assist_orient_enable`。
关闭时平移路径与第 1–8 节完全一致。

```
J6 = [Jv; Jw]           Jw[:,i] = z_i（各关节转轴，底座系）
e_p = p - p_ref
C   = R · R_ref^T       e_R = 0.5·vee(C - C^T)   （轴角，底座系，rad）
omega = Jw · q_dot
F = -Kp·e_p - Dp·v      M = -Kr·e_R - Dr·omega
tau = Jv^T·F + Jw^T·M
```

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `KRX / KRY` | 2.0 N·m/rad | 保持工具水平 |
| `KRZ` | 1.0 N·m/rad | 保持朝向，先软一点 |
| `DRX / DRY` | 0.30 N·m·s/rad | |
| `DRZ` | 0.15 N·m·s/rad | |
| `MMAX` | 0.30 N·m | J0/J5 上限只有 0.6，卡在 50% |

饱和对应的角度：绕 x/y 约 0.15 rad（8.6°），绕 z 约 0.3 rad（17°）。

### 9.1 调试变量（新增）

| 表达式 | 含义 |
| --- | --- |
| `g_cart_assist_orient_enable` | 姿态项开关（可写，默认 0） |
| `g_cart_assist_rot_scale` | 姿态增益缩放（可写，默认 1.0） |
| `g_cart_assist_dbg.orient` | 本周期姿态项是否在输出 |
| `g_cart_assist_dbg.e_R` | 姿态误差，底座系轴角，rad |
| `g_cart_assist_dbg.omega` | 末端角速度，rad/s |
| `g_cart_assist_dbg.M` | 姿态力矩，N·m |
| `g_cart_assist_dbg.tau_rot` | 姿态项分到各关节的力矩 |
| `g_cart_assist_dbg.Jw` | 3×6 角速度雅可比 |
| `g_cart_assist_dbg.sat_mom_cnt` | `\|M\|` 被 MMAX 裁剪的周期数 |

`tau_cart` 现在是平移 + 姿态的**总和**，`tau_rot` 是其中姿态那一部分。

### 9.2 第一次上机

1. 先保持 `orient_enable=0`，确认平移一切照旧；
2. 在锁定状态把 `orient_enable` 写 1、`rot_scale` 写 **0.3**，再切浮动；
3. 手不碰：`e_R` 应 ≈ 0，`M` ≈ 0，`tau_rot` ≈ 0；
4. 只用手腕**慢慢转**末端 5–10°：
   - `e_R` 应沿转轴方向、和你的转动同号；
   - `M` 应和 `e_R` 反号（抵抗你）；
   - `tau_rot` 在 J3/J4/J5 上最明显；
5. 松手：姿态回到 `R_ref` 附近，不回摆；
6. 稳定后 `rot_scale` 调到 1.0 再试。

**注意**：J5 的力矩上限只有 0.6 N·m，`MMAX` 已经是它的 50%。
如果 `sat_mom_cnt` 一直涨，先把 `rot_scale` 降到 0.5。

### 9.3 已知限制

- 平移项本身不约束姿态，所以只开平移时手腕会跟着漂（第 5.2 节）；
  打开姿态项后这一现象会被抑制。
- `e_R` 用 `0.5·vee(R·R_ref^T)`，角度大时会按 sin 收缩（>90° 后力反而变小），
  适合小角度柔顺，不适合大角度回零。
- 姿态项没有零空间手腕保持，冗余方向的漂移仍可能出现；需要时再加。

## 10. 回弹（K）还是随动随停（只有 D）

这是两种不同的人机交互，**用 `g_cart_assist_k_scale` 一个变量切换，不用重编译**：

| `k_scale` | 松手后 | 静止时出力 | 各向异性体现在 | 适合 |
| --- | --- | --- | --- | --- |
| `1.0` | 弹回 `p_ref` | 有（`-K·e`） | 位移 | "保持位置 / 越推越费劲"演示 |
| `0.3` | 弹回，但慢、软 | 有，较小 | 位移 | 折中 |
| `0.0` | **停在哪就是哪** | **没有** | **速度** | 保留原来的随动随停 |

`k_scale` 只乘 K，不乘 D。所以 `k_scale=0` 时力变成

```
F = -scale * D * v          （不再有 -K*e）
```

阻尼仍是各向异性的（`DX=DY=15`，`DZ=3`，5:1），
快速水平推 0.2 m/s 时约有 3 N，竖直只有 0.6 N。

### 10.1 为什么不能"既要回弹又要随动随停"

弹簧的定义就是"离开参考点就出力"，而随动随停的定义是"停下来不能有力"。
两者只在**参考点跟着手走**时才能共存，那就是另一种结构（leaky reference /
lead-through），不是现在这套固定 `p_ref`。所以这里给的是二选一，而不是折中参数。

### 10.2 实机怎么切

不用改代码、不用重新烧录：

1. 浮动状态下先 `enable=1`、`k_scale=1.0`，确认弹簧正常（第 4–6 节）；
2. 把 `g_cart_assist_k_scale` 写成 `0.0`，等一个周期（10 ms）；
3. 现在拖机械臂：动的时候仍有各向异性阻力，**松手后停在原地**，
   和原来 `fsm_geforce_off` 的随动随停完全一样；
4. 想回到弹簧模式，写回 `1.0`；想重新定参考点，写 `g_cart_assist_recapture=1`。

切换时不用退出浮动，`p_ref` / `R_ref` 不会被重新捕获（`recapture` 才会）。

### 10.3 和重力补偿的关系

**重力补偿没有被改动，也不需要改**：每个周期仍然是

```
tor_set = Gravity_Arm_Run()        // 重力前馈，原样
tor_set += CartesianAssist_Run()   // 阻抗，叠加在上面
```

`k_scale=0` 且静止时 `F=0`、`tau_cart=0`，`tor_set` 就等于原来的重力前馈，
所以"随动随停"自动保留。`k_scale=1` 时多出来的只是弹簧力，
重力前馈依然是原来那份（`tau_grav` 可对比确认）。

注意 `k_scale=0` 时 `g_cart_assist_dbg.e` 仍然会因为拖动而变大，
但它不再产生力——看力请直接看 `F`，不要看 `e`。

### 10.4 回 ref 时的小抖动

`sat_force_cnt` 在涨，说明回程中 `|F|` 顶到了 `FMAX=6 N`，
`F` 被等比裁剪时 **阻尼项也一起被削**，所以在边界附近会略微欠阻尼。
三种处理，按代价从小到大：

1. 用 `k_scale=0.0`：根本没有回程，抖动自然消失（随动随停模式）；
2. 降 `g_cart_assist_scale` 到 0.6–0.7：回程力变小，更不容易顶到 6 N；
3. 改头文件 `CART_ASSIST_FMAX` 或 `DX/DY`：要重编译，最后再动。

只要 `sat_force_cnt` 在涨而 `sat_tau_cnt` 不涨（J0 力矩没超 0.8×0.6 N·m），
就不是安全问题，只是手感在限幅边界上。
